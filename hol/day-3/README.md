# Day 3: build it yourself

Build a pipeline from a first workflow to organization-level merge gates. Try each task before opening its hint. Keep a run URL and a short explanation at every checkpoint.

These labs are derived from **GitHub Actions Training - Day 3 - Build It Yourself.pdf**, pages 1-91. The module names, time boxes and checkpoints follow that deck. M8 deliberately comes before M7.

## Start here

Complete [setup and the Day 2 recap](00-Setup.md). The [facilitator guide](FACILITATOR-GUIDE.md) lists the separate template, organization repositories and permissions that must be prepared.

This update supplies **lab instructions**, not a Tetris application, deployed organization resources, broken-workflow branches or solution branches. Do not copy the Day 2 workflows into the Day 3 practice repository.

## Conventions and corrections to the slides

- Follow this repository's [delivery requirements](../../DELIVERY-REQUIREMENTS.md): file-level `permissions: {}`, then job-level grants; readable full release tags plus an execution lock generated by `gh actions-lock`. The PDF teaches inline SHA pins and file-level `contents: read`. Both approaches aim at immutable execution and least privilege; the labs use the repository convention. [S10](STRETCH.md#s10---immutable-dependencies-and-upgrades) compares the inline-pin alternative.
- Node 20/22 in slide examples are illustrative, not a requirement. Use supported runtimes that the prepared app actually supports; start with Node 24.
- A schedule cannot be proved by running a feature branch manually. M2b separates default-branch schedule evidence from manual smoke tests.
- Required code-owner review applies to every matching owned path. An app PR is not exempt when a catch-all owner exists.
- A production deployment from `main` occurs after merge. Waiting for that deployment does not itself block a PR; the capstone uses a code-owner review as its third merge gate.

These are intentional corrections, not additional exercises. Organization enforcement, API writes and workflow execution still require a facilitator dry run; local documentation checks are not proof that those features work in the training tenant.
